# waybar-workspace на Rust

Полный перенос обработчика рабочих столов Hyprland для Waybar. Все режимы
работают в нативном бинарнике:

```sh
waybar-workspace serve
waybar-workspace watch 1
waybar-workspace status 1
waybar-workspace focus 1
```

Для `watch`, `status`, `focus` нужен номер от 1 до 9. `serve` использует
`WAYBAR_WORKSPACE_DIR`; IPC находится через `XDG_RUNTIME_DIR` и
`HYPRLAND_INSTANCE_SIGNATURE`.

`serve` поддерживает девять файлов JSON и маркер `ready` для `desktop-bar`.
Обновление файлов атомарное; файлы переписываются и Waybar получает сигналы
`SIGRTMIN+номер` только при изменении состояния. Сохраняются классы `workspace`,
`occupied`, `empty`, `active`, `urgent`, `unavailable` и порядок классов.

`watch` печатает JSON при изменении выбранного рабочего стола. `status` получает
снимок занятости и фокуса. `focus` напрямую отправляет в IPC ту же команду
`/dispatch hl.dsp.focus({ workspace = N })`, которую отправлял `hyprctl`;
дополнительный процесс при клике больше не запускается.

Один поток блокирующе читает сокет событий: в простое нет периодических запросов
и пробуждений. Фокус публикуется до обновления числа окон; события одного пакета
объединяются в один запрос занятости. Сохраняется учёт срочных окон, их перемещения,
закрытия и сброса срочности после посещения рабочего стола. После разрыва IPC
выводится `unavailable` и выполняется переподключение через 2 секунды.

JSON разбирается типизированно с помощью `serde`/`serde_json`, без загрузки
ненужных полей. Версии зависимостей зафиксированы в Cargo.lock. Максимальный
ответ IPC — 16 МиБ, событие — 256 КиБ; операции чтения/записи запросов имеют
тайм-аут. Для уведомлений проверяются PID, время запуска и имя Waybar, а сигнал
передаётся через pidfd, исключая отправку другому процессу при повторном использовании PID.

Требования: Linux x86_64 >= 5.3, glibc >= 2.36, системные libc/libgcc_s.
Python и `hyprctl` для работы самого обработчика не нужны.

## Сборка и проверка

```sh
cd optional/rust/waybar-workspace
# При первой сборке на новой машине Cargo скачает зависимости.
cargo build --release --locked
# После загрузки зависимостей сеть не нужна:
cargo build --release --locked --offline
cargo test --release --locked --offline
cargo clippy --locked --offline --all-targets -- -D warnings
cargo fmt --check
python3 -B test_integration.py
```

Интеграционные тесты запускают настоящий бинарник на временных Unix-сокетах.
Проверяются все режимы, события, приоритет фокуса, срочность, переподключение,
дедупликация, права файлов и доставка реальных сигналов тестовому процессу.
Рабочая сессия при этих тестах не изменяется.

## Установка

Из этого каталога после сборки:

```sh
install -m 755 target/release/waybar-workspace ~/.local/libexec/waybar-workspace
```

`install.sh` устанавливает переносимую Python-версию. Rust-версия совместима с
`desktop-bar` и форматом конфигурации Waybar. Для переключения уже запущенного
наблюдателя перезапусти службу Waybar при удобном случае. Для возврата к Python
скопируй `home/.local/libexec/waybar-workspace` из репозитория на то же место.
`optional/workstation/desktop-check` понимает оба варианта.

`benchmark.py` принимает пути к Python-обработчику и собранному бинарнику;
использует временные IPC-сокеты. Измерения и тесты не запускаются установщиком.
